取り込みは cron、失敗は画面に残る

日次レポートを人が作らない、というのが前提です。取り込みは定時に自動で走り、実行ごとの結果はソース単位で記録されます。失敗に気づくのが翌週、という状態をなくします。

定時取り込みと履歴

ソースごとに時刻をずらして毎日走ります。Firestore の大規模スキャンが数分かかるのは正常な挙動で、その所要時間も履歴に残ります。失敗した実行はエラー本文つきで残り、画面の健全性バッジが変わります。

  • 実行ごとの記録 — 開始時刻・行数・所要時間・状態（OK / SKIP / ERROR）
  • エラー本文 — 相手先のステータスとレスポンス。資格情報は含めない
  • 手動実行 — 管理画面から任意のソースを即時に取り込み直せる
  • 健全性バッジ — 全画面の上部に「最終取り込み」と「異常の有無」

差分取り込み

GA4 の BigQuery export は、日次テーブルがその日の約 1 日後に作られ、約 4〜5 日後の最終更新を最後に確定します。Fireboard はテーブルの last_modified_time を見て、前回の取り込み以降に書き換わったテーブルだけを読みます。「直近 N 日」のような決め打ちはしません。

  • 更新テーブルのみ — スキャン対象を確定済みでないテーブルに限定
  • 全量の再取り込み — 必要なときは full モードで全期間を取り直せる
  • 差分と全量の一致確認 — 両モードで同じ値になることを確認した上で運用

コストの可視化

BigQuery のスキャン量を呼び出し元（どの取り込み・どの画面の操作か）ごとに集計し、単価から概算費用を出します。主役は定時の取り込みで、ユーザーの画面操作ではありません — この内訳は見ないと分からないので、画面に出しています。

  • 呼び出し元別 — ingest / API / 未分類のスキャン量とクエリ数
  • 概算費用 — 単価は設定値。請求明細と突き合わせられるよう語彙を揃える
  • 月次推移 — 差分取り込みの効果をスキャン量で確認
